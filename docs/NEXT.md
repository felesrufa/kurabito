# 次にやること(引き継ぎメモ)

新しい会話でこのリポジトリを開いたら、まずこれと `docs/DATA.md` を読むこと。
現在は v0.3.0(在庫登録・期限一覧・対応待ち・書き出し/読み込み・まとめ名ごとの合計・入力途中の下書き・ジャンルの追加と変更)。

## 守ること

- データは端末内(localStorage)だけ。外部送信なし。CSP の `connect-src 'none'` を外さない
- 公開リポジトリなので、持ち主の家の事情がわかる初期値・テストデータを書かない
- ユーザー入力は `textContent` で表示する(innerHTML に入れない)
- データの形を変えたら `docs/DATA.md` を更新し、読み込み時の互換(古いバックアップ)を保つ
- 変更したら `sw.js` の `CACHE` と `app.js` の `VERSION` を上げる(上げないとiPhoneで古い版が残る)
- iPhoneのホーム画面アプリ(Safari)で使う前提。ボタンは押しやすい大きさに

## 預かりリスト(上から順に)

### 1. シチュエーション選び(大きい機能)

- 「備え」タブで、避難先(自宅避難/避難所/野営)× 季節(夏/冬)× 災害(地震/台風/津波/富士山噴火)を選ぶ
- 必要数と持っている数を突き合わせて、足りない分を出す(例:水 必要42L/ある32L → あと10L)
- 条件は持ち物ではなく**必要リストの側**に付ける。持ち物とはまとめ名で突き合わせる
- 必要数は「人数×日数」で自動計算し、手で上書きもできる(おむつは乳幼児の人数だけ、など)
- 家全体での最低個数(合計に対する判定)もここで扱う
- 必要リストの中身は、公的資料(東京備蓄ナビなど)を裏取りしてたたき台を作り、
  公的資料/体験談/自分メモの印を付ける。調べものが多いので、作る前に相談すること

#### 決まったこと(2026-11-13)

- 必要リストの初期値は「足りないより多すぎるほうがいい」。公的資料や一般的なチェックリストに
  載っている物は、理由があるはずなので一度は入れる。要らなければ持ち主があとで消す
  (例:使い捨てカイロは「冬」の条件付きで入れる)
- 達成率は**シチュエーション(避難先×季節×災害)ごと**に出す。全体で1つの%は出さない
  - 基本は選んでいる組み合わせ1つだけを出す。24通りを全部並べない
- 必要リストの各項目に優先度を3段で付ける(命や衛生に関わる/あると助かる/あれば快適)
  - %には最優先の段の達成率も添える(例:「冬/野営/地震 70%(最優先は100%)」)
  - 最優先が1つでも欠けていたら、%より先に目立たせる
- できてない項目は、最優先の段から、足りない割合の大きい順に並べる。量と割合の両方を出す
  (例:「水 あと10L(必要の24%不足)」)
- 必要リストには品名ではなく役割を書いてもよい(例:「保温(冬)」をカイロ・アルミブランケット・
  防寒着のどれで満たしてもよい)。持ち物とはまとめ名で突き合わせる

#### 進め方

1. 会話のClaudeが公的資料(首相官邸の「備え」チェックリスト、東京備蓄ナビなど)の本文を読み、
   必要リストのたたき台(品目・必要数の式・条件・優先度・出典)を表で作る
2. 持ち主が見て足し引きする
3. 最初の版の範囲を決める(24通りを一度に作るか、「自宅避難」から始めるか)
4. Claude Code への指示を作って実装
