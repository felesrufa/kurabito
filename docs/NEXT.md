# 次にやること(引き継ぎメモ)

新しい会話でこのリポジトリを開いたら、まずこれと `docs/DATA.md` を読むこと。
現在は v0.1.0(在庫登録・期限一覧・対応待ち・書き出し/読み込み)。

## 守ること

- データは端末内(localStorage)だけ。外部送信なし。CSP の `connect-src 'none'` を外さない
- 公開リポジトリなので、持ち主の家の事情がわかる初期値・テストデータを書かない
- ユーザー入力は `textContent` で表示する(innerHTML に入れない)
- データの形を変えたら `docs/DATA.md` を更新し、読み込み時の互換(古いバックアップ)を保つ
- 変更したら `sw.js` の `CACHE` と `app.js` の `VERSION` を上げる(上げないとiPhoneで古い版が残る)
- iPhoneのホーム画面アプリ(Safari)で使う前提。ボタンは押しやすい大きさに

## 預かりリスト(上から順に)

### 1. 合計量の表示

- 品に欄を追加
  - **まとめ名**(`group`):空欄なら品名をそのまま使う
  - **1つあたりの量**(`amountPer`)と**その単位**(`amountUnit`):例 0.5 L、2 L、50 回分
- まとめ名が**一致するものだけ**を足す。品名が似ているだけでは足さない
  - 例:電池(単三)と電池(単四)は混ぜない
  - 比較のときは、全角/半角の英数字・かっこ・前後の空白の違いは同じとみなす。読みが同じだけ(水/みず)は別
- 単位が違うもの(L と 個 など)は、まとめ名が同じでも足さない
- ml→L、g→kg は自動で換算
- 1つあたりの量が空欄なら、個数×単位でそのまま数える
- 一覧の上に、まとめ名ごとの合計と内訳(置き場所別)を出す
  - 例:「水 合計32L(押し入れ 24L・防災袋 8L)」← 500ml×24本、2L×6本、2L×4本
- まとめ名の入力欄には、使ったことのあるまとめ名を候補として出す
- 品名は正確な商品名でよい(例:品名「コカ・コーラ 500ml」、まとめ名「コーラ」)

### 2. 入力途中の下書き保存

- iPhoneで別のアプリに移ってから戻ると、入力途中の内容が消えた(アプリが閉じられて読み込み直しになったと思われる)
- 入力するたびに下書きを端末に保存し、次に開いたときに「書きかけの入力があります。続けますか?」と出して戻す
- 保存か「やめる」で下書きを捨てる

### 3. ジャンルを自由に追加・変更

- 例:「文房具」「学校用品」を足したい
- 最初の4つ(食品・防災グッズ・日用品・その他)は残す
- 使っている品があるジャンルを消すときは「その他」に移すか確認する

### 4. シチュエーション選び(大きい機能)

- 「備え」タブで、避難先(自宅避難/避難所/野営)× 季節(夏/冬)× 災害(地震/台風/津波/富士山噴火)を選ぶ
- 必要数と持っている数を突き合わせて、足りない分を出す(例:水 必要42L/ある32L → あと10L)
- 条件は持ち物ではなく**必要リストの側**に付ける。持ち物とはまとめ名で突き合わせる
- 必要数は「人数×日数」で自動計算し、手で上書きもできる(おむつは乳幼児の人数だけ、など)
- 家全体での最低個数(合計に対する判定)もここで扱う
- 必要リストの中身は、公的資料(東京備蓄ナビなど)を裏取りしてたたき台を作り、
  公的資料/体験談/自分メモの印を付ける。調べものが多いので、作る前に相談すること
