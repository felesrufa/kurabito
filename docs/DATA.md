# kurabito データ設計

データはすべて端末の中(ブラウザの localStorage)に、1つのJSONとして保存する。
サーバーには何も送らない。書き出し/読み込みも同じJSONを使う。

後から足す機能(必要リスト・条件フィルタ・人数計算・Tips・採点)も、
最初からこの形に入るように場所だけ用意してある。第1版で使うのは ★ の付いた部分。

```jsonc
{
  "app": "kurabito",
  "schemaVersion": 1,
  "exportedAt": "2026-11-12T13:30:00+09:00",   // 書き出し時のみ

  // ★ 設定
  "settings": {
    "leadDays": 30,          // 期限の何日前から「対応待ち」に出すか(品目ごとに上書き可)
    "planDays": 7            // 何日分を備えるか(必要数の計算に使う。v2〜)
  },

  // ★ ジャンル(並び順のまま)。設定タブで追加・名前の変更・並べ替え・削除ができる
  "genres": [
    { "id": "food",   "name": "食品" },        // 最初の4つ。id は固定で、消せない(名前は変えられる)
    { "id": "bousai", "name": "防災グッズ" },
    { "id": "daily",  "name": "日用品" },
    { "id": "g_xxxxxxxx", "name": "(足したジャンル)" },   // 足したものは g_ で始まる id
    { "id": "other",  "name": "その他" }       // 行き先の受け皿。常に残す
  ],

  // ★ 持ち物(在庫)
  "items": [
    {
      "id": "i_xxxxxxxx",
      "name": "保存水 2L",
      "yomi": "ほぞんすい",        // よみがな(並び順用。"" = 品名で並べる)。ひらがなにそろえて持つ
      "genre": "food",             // genres の id。一覧にない id は other として読み込む
      "quantity": 6,
      "unit": "本",
      "group": "水",               // まとめ名(合計に使う)。"" = 品名をそのまま使う
      "amountPer": 2,              // 1つあたりの量(null = 個数×unit でそのまま数える)
      "amountUnit": "L",           // その単位。amountPer と必ずセット(片方だけなら両方なしにする)
      "minQuantity": 6,            // これを下回ったら「対応待ち」(null = 見ない)
      "mark": "",                  // 買い物の印。"" = なし / "buy" = 買いたい / "avoid" = もう買わない
      "avoidReason": "",           // もう買わない理由。mark が "avoid" のときだけ持つ(ほかは "")
      "bestBefore": "2028-03-01",  // 賞味期限(null可)
      "useBy": null,               // 使用期限(電池・薬・消火器など。null可)
      "reviewAt": null,            // 見直し日(おむつのサイズ確認など。null可)
      "leadDays": null,            // この品だけの「何日前から」。null = settings を使う
      "location": "",              // 置き場所
      "maker": "", "model": "",    // メーカー・型番(採点用)
      "size": "",                  // サイズ(おむつ等)
      "memo": "",
      "tags": [],                  // v2: 条件フィルタ用のタグ
      "createdAt": "...", "updatedAt": "..."
    }
  ],

  // ★ 対応待ちの状態(スヌーズ)
  // キーは「どの品の・どの知らせか・どの日付/状態に対してか」。
  // 期限の日付が変わればキーも変わるので、また出てくる。
  "alerts": {
    "i_xxxxxxxx|bestBefore|2028-03-01": { "snoozeUntil": "2026-11-15" },
    "i_yyyyyyyy|useBy|2027-01-01":      { "doneAt": "2026-11-12" }
  },

  // v2: 家族(人数計算用)。名前は入れない(「大人1」「子」程度)
  "people": [
    { "id": "p_xxxx", "label": "大人1", "kind": "adult" }  // adult / child / infant / elder
  ],

  // v2: 必要リスト
  "requirements": [
    {
      "id": "r_xxxx",
      "name": "飲料水",
      "unit": "L",
      "match": { "names": ["水"], "itemIds": [] },      // どの持ち物と突き合わせるか
      "formula": {
        "type": "perPersonPerDay",   // perPersonPerDay / perPerson / fixed
        "amount": 3,
        "personKinds": []            // 空 = 全員。["infant"] ならおむつ等
      },
      "override": null,              // 手で決めた数(計算より優先)
      "conditions": {                // 空配列 = すべての条件で必要
        "place":  [],                // home / shelter / camp
        "season": [],                // summer / winter
        "hazard": []                 // quake / typhoon / tsunami / eruption
      },
      "origin": "public",            // public(公的資料) / experience(体験談) / mine(自分メモ)
      "sources": [{ "title": "", "url": "" }]
    }
  ],

  // v3: Tips
  "tips": [
    {
      "id": "t_xxxx",
      "text": "",
      "status": "verified",          // verified(公的資料で確認) / experience(体験談) / mine(自分メモ)
      "related": { "names": [], "genres": [] },   // genres はジャンルの id(表示名ではない)
      "sources": [{ "title": "", "url": "" }]
    }
  ],

  // v4: 採点(会話のClaudeが作ったファイルを取り込む。自動でも同じ形)
  "scores": [
    {
      "maker": "", "model": "",
      "category": "簡易トイレ",
      "criteria": [
        { "name": "固まる量", "score": 4, "max": 5, "basis": "", "sources": [] }
      ],
      "unknown": ["耐荷重"],          // 裏が取れなかった項目(点を付けない)
      "scoredAt": "2026-11-12",
      "scoredBy": "claude-chat"       // claude-chat / auto
    }
  ]
}
```

## ジャンル

- 品は表示名ではなく `id` でジャンルを指す。名前を変えても品のひも付けは切れない
- 最初の4つ(`food` / `bousai` / `daily` / `other`)は消せない。足したジャンルの `id` は `g_` + 英数字
- 同じ名前は作れない。比べ方は合計のまとめ名と同じ(NFKC でそろえて前後の空白を取る)
- 品があるジャンルを消すときは、確認のうえ品を `other` に移してから消す
- 読み込みの互換
  - `genres` がない古いバックアップ(v0.2.0 まで)は、最初の4つだけとして読み込む
  - 最初の4つのどれかが欠けていたら、元の名前で補う。形のおかしい項目や `id` の重複は捨てる
  - 同じ名前が2つ入っていたら、後のほうに「(2)」を付けて区別する(品のひも付けを残すため)
  - 品の `genre` が一覧にないときは `other` にする。下書きのジャンルが消されていた場合も同じ
- `genres` は v0.3.0 で追加(`schemaVersion` は 1 のまま)。名前は20文字まで、全部で50個まで

## よみがな(yomi)

漢字の品名を読みの五十音順に並べるための、任意の欄。空なら従来どおり品名で並ぶ。

- 保存・読み込み・取り込みのときに、NFKC にそろえ、カタカナをひらがなに直して持つ
  (長音「ー」はそのまま)。前後の空白を取り、100字で切る
- 並び順の鍵は、`yomi` があれば `yomi`、なければ `name`。その鍵のカタカナもひらがなに直してから
  `localeCompare(…, 'ja')` で比べる。カタカナの品名と、よみがな付きの漢字の品名が五十音で混ざる
  - 対象は、一覧の「名前順」と、ほかの並び順で同順位のときの決め方。まとめ名の合計の並びは変えない
  - よみがなのない漢字の品名は、従来どおり、かなの後ろに並ぶ
- 検索語は `yomi` にも当てる(検索語のカタカナをひらがなに直して部分一致)。品名の候補も同じ
- 「この品をコピー」では引き継ぐ
- `yomi` は v0.4.1 で追加。ない古いバックアップは `""` として読み込む(`schemaVersion` は 1 のまま)。
  書き出しには含まれる

## 買い物の印(mark)

持っているかどうか(数量)とは別に、品に印を1つ付けられる。別のタブや別の保存場所は作らない。

- `""` なし / `"buy"` 買いたい / `"avoid"` もう買わない。この3つ以外は `""` として読む
- 買いたい: 持っていない物(数量0)にも、在庫はあるが補充したい物にも付ける。
  一覧を「買いたい」で絞り込めば買い物リストになる。一覧の「買った」は、印を外した編集画面を
  開くだけで、保存するまで何も変えない(数量が0なら1にして出す)
- もう買わない: 試して失敗した物の記録。**理由(`avoidReason`)は必須**で、画面では空のまま保存できない
  (空白だけも不可)。画面上の文字数制限はない
  - 読み込み時だけは、理由が空でも弾かない。長さは 10000 字で切る
  - `avoidReason` は `mark` が `"avoid"` のときだけ残す。印を変えたら `""` になる
- **在庫の数え方は数量だけ**。印では除外しない。もう買わない品でも、手元に残っている分は合計に入る。
  処分したら数量を0にして、印と理由は残す
- 印のある品(`buy` / `avoid`)には、在庫不足の知らせ(`minQuantity`)を出さない
- `mark` / `avoidReason` は v0.4.0 で追加。ない古いバックアップは `""` として読み込む
  (`schemaVersion` は 1 のまま)。書き出しにはどちらも含まれる

## 合計(まとめ名ごと)

一覧の検索窓の下に、まとめ名ごとの合計と置き場所別の内訳を出す。保存はせず、表示のたびに計算する。

- 絞り込み中(検索・ジャンル・置き場所・まとめ名・買い物の印のどれか)は、絞り込んだ品だけで集計し、
  見出しを「絞り込み中の合計」にする
- 合計の行をタップすると、そのまとめ(まとめ名+単位)だけに絞り込む。この絞り込みは保存しない
- 数量 0 の品は合計の行を作らない(足しても変わらないため)

- まとめ名(`group`、空なら `name`)と単位が**どちらも一致するもの**だけを足す
- 比べるときは NFKC でそろえて前後の空白を取る(全角/半角の英数字・かっこの違いは同じ)。
  読みが同じだけ(水/みず)は別もの
- 量は `amountPer` があれば `quantity × amountPer`(単位は `amountUnit`)、なければ `quantity`(単位は `unit`)
- ml・ミリリットル→L、g・グラム→kg は換算してから足す。それ以外の単位は換算しない
- 1品だけで `group` も `amountPer` もないものは、一覧と同じ内容になるので合計には出さない
- `group` / `amountPer` / `amountUnit` は v0.2.0 で追加。ない古いバックアップは「なし」として読み込む
  (`schemaVersion` は 1 のまま)

## 入力途中の下書き

品の登録・編集画面で入力するたびに、localStorage の別のキー `kurabito:draft` に保存する。
バックアップ(書き出し)には含めない。

```jsonc
{
  "editingId": "i_xxxxxxxx",      // 編集中の品。追加の途中なら null
  "values": { "name": "...", "quantity": "1" },   // 入力欄の中身(すべて文字列)
  "savedAt": "2026-11-12T13:30:00.000Z"
}
```

- 「この品をコピー」で開いた新規登録フォームの下書きは、別のキー `kurabito:draft-copy` に保存する
  (同じ形に、引き継ぐタグ `tags` が加わる。`editingId` は常に null)。
  コピー元の編集の書きかけ(`kurabito:draft`)には触らず、コピーを閉じたあとで続けるか聞く
- 次に開いたときに下書きがあれば「書きかけの入力があります。続けますか?」と聞く
  (コピーの下書き → ふつうの下書き の順に1つずつ)
- 保存・「やめる」・削除で登録画面を閉じたとき、「捨てる」を押したとき、「すべて消す」で消える

## 一覧と登録画面の表示の決まり(v0.4.1。データは変えない)

- **束ねて表示**: 一覧では、品名が同じ(NFKC+前後の空白を取って同一)で、買い物の印も同じ品を一行に束ねる。
  中の行は期限の近い順。束の合計は、単位がすべて同じときだけ出す。束ねるのは描画だけで、
  絞り込み・検索・並び順・まとめ名の合計・件数は、品1つずつのまま
- **この品をコピー**: 同じ内容の新規登録フォームを開く。数量・賞味期限・使用期限・見直し日・買い物の印・
  もう買わない理由は空にし、ほか(タグ・よみがなを含む)は引き継ぐ。保存するまで何も作らない
- **「もう買わない」に似た登録への注意**(保存は止めない): 印が `avoid` の品と、次のどちらかで一致したら出す
  1. 品名から、容量・本数の表記(500ml / 2L / 24本 / ×6 など)と空白・記号を取り除いた名前が、2文字以上で一致
  2. メーカーと型番がどちらも入っていて、どちらも一致
- **品名の候補**: 新規登録とコピーのフォームで、品名が2文字以上のとき、登録済みの品から最大5件。
  品名は部分一致(かなの読み替えなし)、よみがなも部分一致。「もう買わない」の品は赤い札を付けて先に出す

## 「対応待ち」に出る条件(第1版)

| 種類 | 出る条件 | 消える条件 |
|---|---|---|
| 期限(賞味・使用) | 数量が1以上で、期限まで `leadDays` 日以内、または期限切れ(数量 0 の品は出さない) | 日付を更新する / 「このままでいい」を押す / スヌーズ中 |
| 在庫不足 | `quantity < minQuantity`、かつ買い物の印がない(`mark` が `""`) | 数を更新する / スヌーズ中 |
| 見直し日 | `reviewAt` が今日以前 | 見直し日を更新する / 「確認した」を押す / スヌーズ中 |

スヌーズは「明日」「3日後」「1週間後」。期間が過ぎるとまた出てくる。
